# 明日方舟基建排班表检查和翻译

## 任务目标

用户提供一份明日方舟基建排班 excel 表格，你需要检查该 excel 是否符合排班规则，和/或将其翻译为排班 txt 文件格式。

## 明日方舟基建排班表

该任务基于游戏《明日方舟》的基建系统。

明日方舟基建中有以下站点：

- 控制中枢
- 会客室
- 制造站
- 贸易站
- 发电站
- 办公室
- 加工站
- 训练室
- 宿舍
- 活动室

每个站点可以安排干员工作、休息或活动。

控制中枢、会客室、制造站、贸易站、发电站、办公室是生产站，干员在这些站点工作时有效率加成，可以产出产物，但是需要消耗心情。加工站、训练室为非生产站，干员在这些站点工作时仅为其他站点提供效率加成，本身没有效率加成，也不产出产物。宿舍可供干员休息，恢复心情。活动室在本技能中不涉及。

干员有基建技能，基建技能决定了干员在不同站点的效率加成。

干员有精英化等级（精英 0、精英 1、精英 2），干员会随着精英化等级的提升而获得新的基建技能或者提升现有基建技能的效率加成。因此，干员需要特定的精英化等级才能在某些站点工作。

干员在生产站工作时会消耗心情，在宿舍休息时会恢复心情。若干员心情归零，会注意力涣散，此时干员的效率加成会降低。

因此，玩家需要合理安排干员的工作和休息，以保证干员的心情和效率。这产生了 “基建排班表” 的概念。

基建排班表是玩家为干员安排工作和休息的计划表。基建排班表由 2 ~ 3 个队列组成，每个队列指定了什么干员在什么站点工作或休息，每个队列的干员在同一时间段工作或休息。

## excel 排班表格式

### 文件结构

excel 排班表由队列轮换表、效率表、产出表组成。

### 队列轮换表

#### 列结构

提供的 excel 排班表共 5 ~ 7 列。

每列依次为：站点名称、队列 1 进驻的干员、队列 1 的效率、队列 2 进驻的干员、队列 2 的效率、队列 3 进驻的干员、队列 3 的效率，其中，“队列 3 进驻的干员” 和 “队列 3 的效率” 为可选列，如果排班表只有 2 个队列，则队列 3 不存在。

除 “站点名称” 列之外，每 2 列为一组队列：首先写干员名称，然后写效率百分比。

#### 多行站点

当一个站点有多个干员时，第一行写第一个干员及其效率，后续行补充更多干员（后续行的站点名称列为空）。

例如，

```
"制造站 1
作战记录"	远牙	42%	温蒂	90%	远牙	42%
	野鬃	42%	异客	30%	野鬃	42%
	灰毫	42%	冬时	30%	灰毫	42%
```

表示这个站点是第 1 个制造站，生产的产物为中级作战记录，在这个站点中，队列 1 进驻的干员为远牙、野鬃、灰毫，3 人的效率分别为 42%、42%、42%；队列 2 进驻的干员为温蒂、异客、冬时，3 人的效率分别为 90%、30%、30%；队列 3 进驻的干员为远牙、野鬃、灰毫，3 人的效率分别为 42%、42%、42%。

#### 百分比的含义

- 每个干员右侧的百分比是其单人效率
- 如果某干员右侧没写百分比，则表示该干员属于一个干员组合，整个干员组合有一个整体的效率。

### 效率表

本技能用不到效率表，请忽略它。

### 产出表

包含整个排班表的产出数据。

## Txt 排班表格式

### 文件结构

```
排班表标题（可多行）
-=-
排班表描述（可多行）
-=-
统计数据行
队列说明行
站点1标题
站点1类型
站点1队列1干员 | 站点1队列1描述
站点1队列2干员 | 站点1队列2描述
站点1队列3干员 | 站点1队列3描述
---
站点2标题
站点2类型
站点2队列1干员 | 站点2队列1描述
站点2队列2干员 | 站点2队列2描述
站点2队列3干员 | 站点2队列3描述
...
===
另一区块
...
```

### 分隔符

- `-=-`：分隔排班表标题、排班表描述、排班表内容
- `---`：分隔同一区块内的不同站点
- `===`：分隔不同区块

### 排班表标题、排班表描述

排班表标题、排班表描述可能会在 excel 的开头几行中提供。如果未提供，则忽略。

### 站点标题

站点标题能且仅能是以下之一。

- 控制中枢
- 会客室
- 制造站（中级作战记录）
- 制造站（赤金）
- 制造站（源石碎片）
- 贸易站（龙门商法）
- 贸易站（开采协力）
- 发电站
- 办公室
- 加工站 / 训练室
- 宿舍

### 站点类型

站点类型能且仅能是以下之一。

- 控制中枢
- 会客室
- 制造站
- 贸易站
- 发电站
- 办公室
- 宿舍

如果站点标题是 “加工站 / 训练室”，则站点类型为 “办公室”。除此特例之外，站点类型必须等于站点标题去除括号及括号中的内容。

### 队列格式

每个站点包含 2 ~ 3 行，每行对应该站点的 1 个队列，用 `|` 分隔干员和描述。

干员用空格分隔，干员名后面跟精英化等级。

例如，

```
制造站（中级作战记录）
制造站
远牙2 野鬃2 灰毫2 | 126%
温蒂2 异客2 冬时1 | 150%
远牙2 野鬃2 灰毫2 | 126%
```

表示站点为生产中级作战记录的制造站，在该站点中，队列 1 进驻的干员为远牙、野鬃、灰毫，3 人的精英化等级分别为 2、2、2，整个队列的效率为 126%；队列 2 进驻的干员为温蒂、异客、冬时，3 人的精英化等级分别为 2、2、1，整个队列的效率为 150%；队列 3 进驻的干员为远牙、野鬃、灰毫，3 人的精英化等级分别为 2、2、2，整个队列的效率为 126%。

特例：出现干员 Lancet-2 时，必须写成 `Lancet-20!`，需要在精英化阶段数字后面加上 `!`。

## 翻译规则

一些tips：

- excel 里的作战记录制造站中的”35”表示任意35%作战记录的干员，在txt里需要替换为实际的干员。有这些干员：断罪者1、食铁兽2、酒神2、弑君者2、裂响2。你需要确保每个干员最多工作2个队列，并且同一个队列不能出现重复的干员。
- excel 里的源石碎片制造站中的"35”表示任意35%源石碎片效率的干员，有这些干员：艾雅法拉0、炎熔1、地灵1、锡兰2。你需要确保每个干员最多工作2个队列（除非是被菲亚梅塔007的干员）。
- 发电站空白的20%是任意干员，需替换为实际干员，可选的干员有：“格雷伊0、澄闪2、雷蛇2、炎狱炎熔2”
- “莱茵生命”为任意莱茵生命干员，需替换为”白面鸮0、梅尔0、赫默0“
- 加工站/训练室、宿舍里面放的“煌、逻各斯、迷迭香、电弧、烛煌”都是精0即可，即写”煌0“等，除非这里面的干员出现在了其他站中（比如，如果迷迭香出现在了制造站中，那么迷迭香要写2）
- 除了上面我说的之外，阿米娅、夕、诗怀雅、Lancet-2、斥罪都是精0就行，砾精1就行。
- Lancet-2需要写"Lancet-20!"
- excel中，菲亚梅塔以及其右侧那个干员不需要写进txt中。

### 排除规则与 description 更新

**菲亚梅塔及其右侧配对干员** 不写入宿舍站点中。
示例：`菲亚梅塔	但书` → 两者都不写。

**同时需要更新 description 行**：description 中 `菲亚梅塔 007` 后面的干员列表，正是宿舍 excel 中菲亚梅塔**右侧的所有配对干员**（去重后按顺序列出，中文顿号分隔）。

例如宿舍 excel：

```
宿舍	菲亚梅塔	八幡海铃	菲亚梅塔	但书
```

菲亚梅塔的右侧配对干员为：八幡海铃（Q1）和 但书（Q2），所以 description 写：

```
菲亚梅塔 007 八幡海铃、但书
```

注意菲亚梅塔和这些干员**只在宿舍站点中排除**，description 中仍然保留。

### 占位符干员分配规则

**核心原则：用到的干员数量越少越好。**

在满足以下硬约束的前提下，让顺序靠前的干员多工作（跨队列复用），从而减少从池子中取用的干员总数。

硬约束：

- 每个干员最多工作 **2 个队列**
- **同一个队列内不能出现重复干员**
- **每个干员至少有一个队列休息**（非 007 干员不能全勤）

以作战记录制造站中的 `35` 占位符为例。

从池子 `断罪者1、食铁兽2、酒神2、弑君者2、裂响2` 中分配：

- 优先让顺序靠前的干员（断罪者1 → 食铁兽2 → 酒神2 → 弑君者2 → 裂响2）跨队列复用
- 例如：制造站1 Q2 用了断罪者1、食铁兽2、酒神2，则制造站2 Q3 应优先复用断罪者1和食铁兽2，而非引入新的干员（弑君者2、裂响2）
- 最终用 3 名干员（断罪者1、食铁兽2、酒神2）覆盖两个队列共 5 个槽位，而不是使用 5 名不同的干员

此原则同样适用于**发电站空白 20% 填充**、**源石碎片 35% 干员**等所有需要从池子中选择干员的场景。

### 效率标注规则

- 每个队列的 `|` 后标注效率
- 单个干员有明确效率的 → 累加后写本站总效率，如 `| 126%`
- 如果 excel 里的效率有小数点，则四舍五入到整数百分比，并写 `| 平均 x%`
- 当龙舌兰 / 可露希尔 / 但书出现在贸易站时，需要在描述中注明“龙舌兰组/可露希尔组/但书组，纸面 x%”。如果龙舌兰和但书同时出现在贸易站，则需要在描述中注明“龙舌兰但书组，纸面 x%”。
- 有特殊情况的 → 写说明文字，如 `| 爱丽丝、车尔尼放高等级宿舍`

### 描述文字保留

原 txt 中的部分描述文字（如 `令心情 < 12，夕心情 ≥ 12`、`爱丽丝、车尔尼放高等级宿舍`）需根据 excel 中对应的条件保留或更新。

### 产出行（Stats 行）计算

排班 txt 的第一段 `-=-` 之后有一行统计数据，格式为：

`EXP {不加速}k + {加速}k | 贵金属 {不加速}k + {加速}k | 龙门币 {不加速}k + {加速}k | 高级凭证 {值} | 合成玉 {值}`

其中各字段从 excel 底部的 **产出表** 中提取：

| 字段                 | excel 参考行   | 参考列          | 处理方式                                            |
| -------------------- | -------------- | --------------- | --------------------------------------------------- |
| EXP（不加速）        | “作战记录” 行  | “不加速” 列     | 四舍五入精确到百位（如 31680 → 31.7k）              |
| EXP（无人机加速）    | “作战记录” 行  | “无人机加速” 列 | 同上                                                |
| 贵金属（不加速）     | “赤金\*500” 行 | “不加速” 列     | 同上（如 61194.44 → 61.2k）                         |
| 贵金属（无人机加速） | “赤金\*500” 行 | “无人机加速” 列 | 同上（如 6850 → 6.9k）                              |
| 龙门币（不加速）     | “龙门币” 行    | “不加速” 列     | 同上（如 53135.60 → 53.1k）                         |
| 龙门币（无人机加速） | “龙门币” 行    | “无人机加速” 列 | 同上（如 12735.21 → 12.7k）                         |
| 高级凭证             | “公招刷新” 行  | “加速后” 列     | 四舍五入保留 3 位小数（如 0.84341 → 0.843）         |
| 合成玉               | “合成玉” 行    | “不加速” 列     | 四舍五入保留整数（如 578.4 → 578），如果为 0 则不写 |

示例：

`EXP 35.8k + 7.1k | 贵金属 46.8k + 8.9k | 龙门币 58.7k + 14.7k | 高级凭证 0.843`
`EXP 0 + 5.5k | 贵金属 62.2k + 6.9k | 龙门币 47.0k + 13.7k | 高级凭证 0.843 | 合成玉 578`

tips:

- exp、贵金属、龙门币四舍五入精确到百位
- 高级凭证四舍五入保留3位小数
- 合成玉四舍五入保留整数
- EXP的产出参考：”作战记录“行，”不加速“列和”无人机加速“列
- 贵金属的产出参考”赤金\*500“行，”不加速“列和”无人机加速“列
- 龙门币的产出参考”龙门币“行，”不加速“列和”无人机加速“列
- 高级凭证的产出参考”公招刷新“行，”加速后“列。
- 合成玉的产出参考”合成玉“行，”不加速“列。

### 排班表一致性校验

翻译完成后，需要检查 excel 排班表是否满足以下约束条件。如果违反，需反馈给用户确认。

#### 规则 1：同队列无重复干员

**每个队列内部不能出现同一名干员两次**（无论精英等级是否相同）。

例如：队列 1 中不能同时出现两个"断罪者"。

#### 规则 2：被菲亚梅塔 007 的干员需出现在每个队列中

description 中 `菲亚梅塔 007` 后面的干员（即菲亚梅塔在宿舍中的配对干员），**必须在每个队列中都出现一次**（可以在不同站点）。

例如 description 为 `菲亚梅塔 007 但书、苍苔`，则但书和苍苔在每个队列中都必须出现恰好一次。

#### 规则 3：非 007 干员不能全勤

**除被菲亚梅塔 007 的干员之外**，其他所有干员**不能在每个队列中都出现**。至少有一个队列中该干员不在上班（即休息）。宿舍中的干员算休息，不算上班。

例如：如果八幡海铃在 Q1、Q2 中都出现了，但在 Q3 中只出现在宿舍，不算违反规则；如果八幡海铃在 Q1、Q2、Q3 的生产站中都有出现，则违反规则。

### 未知干员与可疑数据检查

翻译过程中，如果遇到任何矛盾、可疑之处（包括但不限于以下情况），**必须向用户指出并请求确认**，不能直接相信 excel。遇到任何不确定的情况都要向用户确认，而不是直接翻译或修改 excel 数据。以下是一些需要特别注意的情况：

#### 需要向用户指出的情况

1. **excel 中出现了未知干员或者未知的占位符** → 询问用户是否需要添加到 SKILL.md 中，并询问该干员的精英等级和效率
2. **excel 中干员右侧没有标注效率，但 SKILL.md 中有固定值** → 指出并让用户确认
   - 例如：可露希尔在 excel 中右侧空白，但 SKILL.md 中可露希尔为固定 10%，需指出并询问用户是否遗漏
3. **excel 中的干员效率与"干员效率与精英等级参考表"中的值不一致** → 指出差异，让用户确认
   - 例如：excel 中某干员效率为 40%，但“干员效率与精英等级参考表”中该干员效率为 35%，需指出差异并询问用户
4. **干员出现在不合理的站点** → 指出差异，让用户确认
   - 例如：阿罗玛是赤金制造站干员，如果 excel 中阿罗玛出现在作战记录制造站，则需要指出并询问用户
   - 例如：但书是贸易站干员，如果 excel 中但书出现在其他站点，则需要指出并询问用户
5. **效率计算公式可能与其他干员联动** → 检查联动条件是否满足
   - 例如：砾的效率和苍苔同站、薇薇安娜在控制中枢有关；引星棘刺和贸易站数量、苍苔同站有关，需仔细检查干员效率是否正确

## 翻译步骤

1. **读取 excel 数据**：理解每列的队列归属
2. **逐站翻译**：
   - 控制中枢 → 注意配对列结构
   - 制造站 → 注意 35% 干员的分配
   - 贸易站 → 裁缝→柏喙2，注意整组效率
   - 发电站 → 空白填充
   - 办公室 → 按 excel 直接翻译
   - 会客室 → 按 excel 直接翻译
   - 加工站/训练室 → 莱茵生命→白面鸮0/梅尔0/赫默0
   - 宿舍 → 排除菲亚梅塔及其配对干员
3. **确定精英等级**：按照规则表为每个干员标注等级
4. **标注效率**：根据 excel 百分比计算或引用整组效率
5. **未知干员检查**：检查是否有 SKILL.md 中不存在的干员，向用户询问
6. **一致性校验**：按照上述 3 条规则检查 excel 排班表
7. **验证**：对照 excel 逐站检查干员、效率、等级是否正确
